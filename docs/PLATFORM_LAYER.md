# Veilance B — 추적 플랫폼들을 잇는 공유 원장

## 1. 포지션

Circularise 같은 추적 플랫폼은 각자 고객사 안에서 수집 · 추적 · 공개를 맡는다. 그러나 플랫폼마다 장부가 따로 있어, 같은 재활용 물량이 서로 다른 플랫폼의 두 고객에게 "재활용분"으로 주장되어도 어느 한 플랫폼도 알 수 없다.
Veilance 는 그 위의 **공유 원장**이다. 플랫폼은 화면 · 수집 · ERP 연동을 그대로 쓰고, 로트 이동과 재활용 함량 선언만 Veilance 에 기록한다.

- 같은 물량 · 같은 재활용분은 어떤 플랫폼을 거쳐도 두 번 쓰일 수 없다(사용 식별자, 사전 차단).
- 수량 · 재활용 업체 · 거래 관계는 원장에 드러나지 않는다.
- 인증기관(notified body)은 어느 플랫폼에도 의존하지 않고 원장만으로 선언을 검증한다.

규제 기준점: EU 배터리 규정 제8조와 재활용 함량 계산 · 검증 위임법령 초안(2026-08-12 의견 수렴). 공장 단위 물질 수지, 공급망 전 단계 추적, 인증기관 검증, 10년 보관, EU 역내 재활용분 1.3배 가산(2036년까지).

## 2. 재활용 함량 모델 (컨트랙트 v2 확장)

로트의 `quantity` 는 대상 원소(니켈 · 코발트 · 리튬) 함유량 kg 로 본다. 로트는 그 안의 재활용분을 두 칸으로 나눠 가진다.

```text
Lot += recycledEuKg      EU 역내 재활용분 (1.3배 가산 대상)
       recycledOtherKg   그 밖의 재활용분
       (recycledEuKg + recycledOtherKg ≤ quantity)
```

| 작업 | 재활용분 규칙 |
|---|---|
| `issueLot` (1차 원료) | 재활용분 0 으로 고정 |
| `issueRecycledLot` | 인증된 재활용 업체만. 전량 재활용분이며, EU / 기타 구분은 재활용 업체 인증서에 적힌 값으로 회로가 정함 |
| `transferLot` | 보낸 몫과 잔량 사이에 재활용분을 자유 배분(물질 수지 할당). 칸별 합은 보존, 각 로트에서 재활용분 ≤ 수량 |
| `processLots` | 산출 재활용분 ≤ 입력 재활용분 × 산출량 / 입력 합 (칸별, 비례 상한). 수율 손실로 비율이 부풀지 않음 |
| `attestOrder` | 필드 그대로 교체 발행 |

## 3. 공장 · 기간 단위 재활용 함량 선언

위임법령 초안은 모델 · 연도 · 공장별로 계산한다. 회로 크기가 고정이므로 기간 합산은 **비공개 누적 계정**으로 한다.

1. `openPeriod(plantId, period, material)` — 제조사가 공장 · 기간 · 원소별 계정을 연다. 같은 조합은 한 번만 열 수 있다(공개 표식 집합). 여러 계정을 열어 유리한 것만 고르는 것을 막는다.
2. `consumeIntoPeriod()` — 보유 로트 하나를 소비해 계정에 수량과 재활용분을 더한다. 로트와 이전 계정은 소비되고 새 계정이 발행된다. 원장에는 사용 식별자 둘과 새 commitment 하나만 남는다.
3. `declareShare(plantId, period, material, declaredBps)` — 계정을 소비하며 `declaredBps ≤ (기타 + EU × 1.3) / 합계` 를 증명하고, 선언값과 총량 커밋먼트를 공개 기록한다. 이후 그 계정은 더 쓸 수 없다.

공개되는 것: 제조사 식별자(해시), 공장 · 기간 · 원소, 선언 비율, 투입 총량의 커밋먼트 `H(총량, salt)`. 비율은 배터리 여권에 어차피 공개되는 값이다.
공개되지 않는 것: 투입 총량, 재활용 업체, 로트별 재활용분, 공급사.

**완결성 확인.** 체인은 공장의 실제 생산량을 모른다. 제조사가 1차 원료 로트를 계정에 넣지 않으면 비율이 부풀 수 있다. 그래서 선언은 총량을 숨긴 커밋먼트를 함께 기록하고, 제조사는 (총량, salt) 를 인증기관에게만 건넨다. 인증기관은 이를 공장 생산 기록과 대조한다(`checkDeclaredTotal`). 체인 밖 감사가 필요한 유일한 지점을 이 한 숫자로 좁힌다.

## 4. 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| B-1 | 컨트랙트: 재활용분 필드, 재활용 업체 인증, 기간 계정과 선언 | 완료 (시뮬레이터 테스트, 증명 키 생성) |
| B-2 | 에이전트: 플랫폼용 다중 회사 API(회사 계정, 회사 측 키), 대납 | 완료 — [agent/API_V2.md](../agent/API_V2.md), 노드와 대납 서버를 별도 프로세스로 로컬 데브넷 검증 |
| B-3 | 웹: 인증기관 검증 화면, 소규모 재활용 업체 입력 화면 | 완료 — 웹 `/v2`(회사 · 관리자)와 `/v2/verify`(인증기관 · 구매사, 로그인 없음). 로컬 데브넷에서 브라우저로 전체 흐름 확인 |

## 5. 알려진 한계

- 첫 단계 진실성: 재활용 업체가 없는 물량을 발행하는 것은 막지 못한다. 위조 가능 지점은 인증된 발행처로 좁아진다.
- 배터리 모델별 할당은 범위 밖. 지금은 공장 · 기간 · 원소 단위만.
- 제조 공정 폐기물(pre-consumer)과 사용 후 폐기물(post-consumer) 구분은 아직 없음.
- 플랫폼 참여 동기는 기술 밖의 문제. 중립 주체(인증기관 · 컨소시엄)가 필요.
